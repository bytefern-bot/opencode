opencode TUI 到 Server API 核心流程

从打开 TUI 开始：主线程启动 Worker，TUI 通过 SDK 调用内置 server 或外部 HTTP server；server 用 workspace routing 选择目录，再加载 InstanceContext，最后由 SessionPrompt 驱动模型流、工具调用、权限和事件回放。

打开 TUI

TUI 命令入口

解析 project、--session、--continue、--prompt、model/agent，切换到目标目录。

Worker 与传输方式

默认走 in-process RPC：TUI fetch 被转成 worker RPC，再调用 Server.Default().app.fetch。

外部服务模式

显式 port/hostname/mDNS 时，worker 调 Server.listen，TUI 直接对 HTTP URL 发请求。

SDK 启动加载

SDK 上下文

createOpencodeClient 绑定 baseUrl、directory、headers、fetch；事件用 global.event 或 RPC 转发。

项目同步

启动时读取 path.get 和 project.current，触发 server 侧 instance 初始化。

界面状态预加载

阻塞加载 config/providers/agents；后台加载 command、LSP、MCP、formatter、session status、VCS。

服务端边界

HTTP API 路由

所有实例 API 经过 Authorization、WorkspaceRoutingMiddleware 和 InstanceContextMiddleware。

工作区路由

根据 ?workspace、session.workspaceID、?directory 或 x-opencode-directory 决定目标。

实例加载

按目录缓存 InstanceContext；首次请求会 project discovery，然后运行 bootstrap services。

用户提问

新建会话

没有 session 时先调 session.create，创建会话并带上 agent/model/workspace。

提交消息

普通输入调 session.prompt → POST /session/:id/message；shell 和 slash command 走独立接口。

智能体主循环

落库 UserMessage/Part，装配上下文、工具 schema、权限规则，调用 LLM stream 并执行工具循环。

交互回路

事件流

GET /event 推送 server.connected、session.next.*、tool.*、permission/question 等事件。

用户决策

权限弹窗回复 permission.reply；模型提问回复 question.reply 或 reject。

状态补拉

TUI 通过事件增量更新；必要时再拉 session.get、messages、todo、diff 或 v2 messages。

端到端请求路径
1 打开 TUI 主线程解析参数、chdir、启动 Worker
2 传输 内部 RPC fetch 或外部 HTTP server URL
3 客户端 SDKProvider 建立 client 和 event source
4 预加载 project.current、config、provider、agent、session list
5 路由 Authorization + workspace routing + instance context
6 初始化 project.fromDirectory + InstanceBootstrap
7 提交 session.create 后 POST /session/:id/message
8 智能体 SessionPrompt 装配上下文并调用 LLM stream
9 工具 工具执行、permission/question 交互、结果回灌
10 渲染 /event 增量驱动 TUI 渲染和补拉 hydration

启动阶段 API

GET /event
TUI 最早建立的事件通道；内部模式由 worker 的 global.event RPC 转发。
GET /path
返回 home/state/config/worktree/directory，供 TUI 显示当前实例路径。
GET /project/current
触发当前目录 Project 解析；必要时加载 git worktree、project id 和 sandbox。
config/provider/agent
加载 config.get、config.providers、provider.list、app.agents。

会话与工具 API

POST /session
新问题没有 session 时先创建，写入 agent/model/workspace 等会话元信息。
POST /session/:id/message
普通 prompt 主路径；server 返回 message，同时后台通过事件流持续推送增量。
/command / /shell
slash command 和 shell mode 分流，最后仍进入 SessionPrompt/SessionRunState 管理。
permission.reply
工具 ask/allow/deny 的用户回路；回复后工具继续、失败或阻塞。

Server 内部边界

WorkspaceRouting
本地 workspace 变成 directory；远端 workspace 走 HTTP/WebSocket proxy。
InstanceStore
按 canonical directory 缓存启动结果；dispose/reload 会发 server.instance.disposed。
Bootstrap
先 config、plugin，再并发初始化 reference、LSP、format、file watcher、VCS、snapshot、project。
EventV2Bridge
把 session.next.*、tool、permission、question、heartbeat 转成 TUI 可消费的 SSE/RPC 事件。

读图重点：TUI 本身不直接跑 Agent。它是 SDK 客户端；真正的项目初始化、会话状态、模型流和工具执行都在 server 的 InstanceContext 内完成，再通过事件流同步回 TUI。
