Life of a Prompt：用户输入先进入持久化消息模型，再由主循环装配上下文、调用模型、处理 stream 事件、执行工具，并根据结果继续、压缩或结束。

input and storage

PromptInput

键盘输入、slash command、附件、agent 选择和 subtask 统一进入 prompt 入口。

UserMessage + Part

createUserMessage 解析 text、file、resource、agent part，并先写入持久化状态。

Session Storage

Session、Message、Part、Diff 和 snapshot gitdir 是 UI、恢复、审计与工具回传的共同状态源。

runtime assembly

RunLoop 初始化

读取 compacted 历史，定位 lastUser、lastAssistant、pending task，选择 agent 和 model。

Context Assembly

合并 environment、skills、AGENTS/CLAUDE、config instructions、历史消息和权限规则。

ToolRegistry

按模型暴露 apply_patch 或 edit/write，并注入 MCP、plugin 和动态工具描述。

model and stream

LLM.stream

合并 provider、agent、variant 参数，附带 headers、tools、toolChoice 和 telemetry。

Provider API

OpenAI、Anthropic、Copilot、LiteLLM、GitLab Workflow 通过 SSE 或 provider stream 返回事件。

SessionProcessor

消费 start、reasoning、text、tool-call、tool-result、finish-step、error 等事件。

tool loop

Tool Call

AI SDK tool.execute 进入 Tool.Def.execute，完成 schema 解码和 permission ask。

Hook + Metadata

执行 plugin before/after，更新 metadata、attachments、title，并截断大输出。

Result Feedback

completeToolCall 写 output 或 error；下一轮 runLoop 把 observation 送回模型。

gates

Continue

有 tool call 或需要 replay 时，回到上下文装配，重新进入模型调用。

Compact

上下文接近窗口时生成 anchored summary，保留 head/tail 并 prune 旧工具输出。

Finish

保存 completed、tokens、cost、patch、summary，session 进入 idle 或 error/blocked。

prompt request path
1 Input PromptInput.parts 进入 session prompt
2 Persist UserMessage 和 Part 先落库
3 Init runLoop 选择 agent、model、历史范围
4 Assemble 指令、工具、权限、provider 参数合并
5 Stream AI SDK streamText 调用 provider
6 Parts stream 事件增量写入 message part
7 Tools 执行工具并写回 tool result
8 Gate 判断 continue、compact、blocked、finish
9 Idle 完成后 session 回到可恢复状态

关键分层

message model
不是临时内存 transcript，而是 session/message/part 驱动的持久化状态。
runtime loop
负责并发、cancel、agent/model 选择、上下文装配和循环 gate。
provider edge
ProviderTransform 在请求前适配模型参数、消息格式和输出 token 上限。

工具边界

permission
工具执行前按规则 ask/allow/deny，结果记录在 tool part 状态里。
plugin hook
before/after hook 可以调整行为、记录 metadata 或改变展示信息。
feedback
工具结果不直接结束流程，而是成为下一轮模型输入的一部分。

长上下文

summary
压缩生成 anchored summary，保留最近轮次和关键任务状态。
prune
旧工具输出可裁剪，避免把低价值大文本持续带入上下文窗口。
replay
必要时 replay 上一次用户请求，让压缩后的上下文继续完成任务。

核心校准：opencode 的 Agent Runtime 由持久化 session state 驱动；工具循环、压缩和恢复都围绕同一组 message part 展开。
