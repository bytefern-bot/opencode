opencode 后端模型图

这张图把 HTTP 请求从全局控制面到项目实例的路径展开：先判断是否是 server 级能力，再通过 workspace routing 找到目录或远端目标，最后进入 instance 内部的缓存、业务数据和事件系统。

server/global routing/workspace instance/runtime project/session data event/sync
server scope

Global

整个 opencode server 进程的控制面，不绑定某个项目目录。

  • /global/health
  • /global/config
  • /global/event
  • /global/dispose 清理所有 instances

GlobalBus

全局事件出口，聚合所有 instance 的事件，并携带 directory、project、workspace 信息。

request routing

Workspace Routing

把请求路由到本地目录或远端 workspace。

  • ?directory=...
  • x-opencode-directory
  • ?workspace=...
  • session 关联目录

Workspace

控制平面概念。它描述目标在哪里：本地 directory，或者一个 remote target。

runtime scope

Instance

某个 directory/project 的运行上下文，由 InstanceContext 表示。

  • directory
  • worktree
  • project

InstanceStore

directory → InstanceContext 的 server 级缓存，负责 load、reload、dispose。

InstanceState

服务内部的 per-directory 缓存，instance dispose 时会 invalidate。

business data

Project

持久化的项目实体。Instance 运行时会关联一个 project，Session 也通过 projectID 归属项目。

Session

一次对话或任务记录，属于 project/directory，可选地属于 workspace。

  • sessionID
  • projectID
  • workspaceID?
  • directory

Bus / SyncEvent

Bus 是 instance 内运行时事件；SyncEvent 是可持久化、可同步、可投影的状态变更。

request path
HTTP request 请求进入 opencode server
Root or Instance global/control 走 Root API，其余走 Instance API
Workspace Routing 解析 directory、workspace 或 session 归属
InstanceStore 按 directory load 或复用 InstanceContext
InstanceRef 把当前 instance 注入 Effect context
Handler 读写 project、session、file、vcs、provider 等服务
Events Bus 发布运行时事件，SyncEvent 记录状态变化

缓存与生命周期

InstanceStore
缓存 directory → InstanceContext；/instance/dispose 清一个，/global/dispose 清全部。
InstanceState
每个服务自己的 per-directory 状态缓存，比如 Bus、SessionStatus、LSP 相关状态。
dispose
先返回 HTTP response，再由 lifecycle middleware 执行清理，避免当前请求被提前破坏。

概念边界

global
server 级控制面；跨项目；适合配置、升级、全局事件和清理全部实例。
workspace
路由目标；可以映射到本地目录，也可以代理到远端。
instance
某个 directory/project 的运行时上下文；大多数业务 API 都运行在这里。
session
持久化业务数据；表示一次对话或任务，归属于 project/directory/workspace。
